# Context Keeper

코딩 에이전트와 하던 일을 놓치지 않은 채, 잠깐 필요한 이야기를 옆에서 해결하고 돌아오게 해 주는 도구입니다.

## 시작한 이유

기능을 구현하다 테스트가 깨졌다고 해 봅시다. 원인을 찾으려면 로그를 읽고, 관련 코드를 살피고, 잘 모르는 개념도 확인해야 합니다. 이 과정을 한 대화에서 이어 가면 메인 작업이 디버깅 기록에 파묻힙니다. 대화를 따로 열면 이번에는 목표와 제약을 다시 설명해야 합니다. 해결한 뒤에는 결론을 요약해 원래 대화에 전달하고, 적용해 달라는 요청도 새로 작성해야 합니다.

Context Keeper는 이 번거로운 왕복을 줄이기 위해 시작했습니다. 사용자는 평소처럼 대화를 이어 갑니다. 대화가 메인 작업에서 벗어나면 시스템이 사이드 대화를 열고, 해결에 필요한 맥락을 챙겨 보냅니다. 논의가 끝난 자리에서는 결과를 반영할지 사용자가 고릅니다.

Codex App Server는 대화를 읽고 포크할 수 있으며, Codex의 Git worktree는 코드 작업 공간을 분리해 줍니다. Context Keeper는 이 기능들을 이용해 분기할 시점을 찾고, 갈라진 대화를 보여 주고, 필요한 결과를 원래 작업으로 가져옵니다.

- [Codex App Server](https://learn.chatgpt.com/ko-KR/docs/app-server)
- [Codex Git worktree](https://learn.chatgpt.com/docs/environments/git-worktrees)

## 사용 흐름

```text
메인 작업
  ├─ 간단한 질문 → 답을 확인하고 닫기
  ├─ 디버깅 → 수정안과 검증 결과를 가져와서 계속하기
  └─ 대안 검토 → 선택한 결론만 가져와서 계속하기
```

사이드 대화가 끝나면 세 가지 중 하나를 선택합니다.

- 적용하고 돌아가기
- 적용하지 않고 돌아가기
- 사이드 대화를 더 이어 가기

간단한 질문은 메인 맥락에 넣지 않아도 나중에 다시 찾아볼 수 있습니다. 구현 방향이 바뀌었거나 버그를 고쳤다면 결론과 근거만 메인 작업으로 가져옵니다. 코드 변경도 함께 생겼다면 대화 내용과 코드 변경을 따로 확인합니다.

어디에서 대화가 갈라졌고 무엇을 가져왔는지는 화면에서 바로 볼 수 있어야 합니다. 자동 분리가 잘못됐을 때는 즉시 되돌립니다. 사이드 대화를 진행하는 동안 메인 코드가 달라졌다면 예전 결과를 그대로 적용하지 않고 다시 확인합니다.

## 첫 MVP

첫 MVP는 디버깅 한 건이 사이드 대화로 빠졌다가 메인 작업으로 돌아오는 과정까지 구현합니다.

- 메인 작업의 목표와 현재 단계, 지켜야 할 제약을 유지합니다.
- 디버깅 대화를 자동으로 분리하고 사용자가 바로 취소할 수 있게 합니다.
- 사이드 대화에 필요한 코드와 작업 맥락을 전달합니다.
- 결론, 근거, 코드 변경, 검증 결과를 정리해 메인 작업으로 돌려보냅니다.
- 대화가 갈라지고 합쳐진 기록을 저장하며, 프로그램을 다시 켜도 같은 자리에서 이어 갑니다.

사용자가 직접 포크 시점을 정하거나 인계용 프롬프트를 복사하지 않고 이 흐름을 끝낼 수 있으면 첫 MVP가 쓸 만하다고 판단합니다.

## 기억으로 이어지는 방식

사이드 대화마다 보존 기간이 다릅니다. 일회성 질문은 기록만 남기고 닫습니다. 승인한 결정과 제약은 현재 프로젝트에 남깁니다. 여러 작업에서 다시 쓰일 만한 내용은 프로젝트 기억으로 올립니다.

이후에는 기억을 관련 코드, 커밋, 테스트, 문서와 연결할 계획입니다. 새 작업을 시작할 때 관련 있는 기억만 골라 에이전트에 전달하고, 결정이 바뀐 과정도 따라볼 수 있게 만듭니다. 대화와 기억이 충분히 쌓이면 더 큰 그래프 저장소와 검색 방식도 검토합니다. 여러 개발 에이전트와 PC·서버를 잇는 작업은 그다음 단계입니다.

대화 기록과 승인 결과는 사용자가 관리하는 저장소에 보관합니다. 특정 서비스의 대화 기록이 사라져도 프로젝트의 결정과 진행 상황은 남아 있어야 합니다.
